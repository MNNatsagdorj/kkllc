# 08 · 구현 로드맵

원칙: 엑셀·수기 프로세스를 가장 먼저 대체하는 것(관리자+기사)부터. 웹 주문은 그다음.

## Phase 1 · MVP — 관리자 + 기사 (≈ 3–4주)

**목표: 주문 등록 → 기사 배정 → 푸시 → 배송 완료가 시스템 안에서 한 바퀴 돈다.**

- [ ] Supabase 프로젝트 생성, `02-data-model.md` 마이그레이션 적용 + 시드(제품 5종, 기사/차량)
- [ ] Auth: 관리자 계정, 기사 계정(전화+PIN), `role` 프로필, RLS 정책
- [ ] `lib/delivery.ts` (BR-1) + `lib/status.ts` (상태 매핑·전이 테이블) + 단위 테스트
- [ ] API: 주문 생성 / 상태 전이(전이 규칙 검증) / 기사 배정 / FCM 토큰 등록
- [ ] 관리자: 칸반 4열 + Realtime, 주문 카드, 신규 주문 드로어(자동 합계·중량·100ш 미터), 기사 배정 + 용량 경고(BR-5)
- [ ] 기사 PWA: manifest/SW, 오늘 리스트, 상세(전화 tel: / 지도 딥링크 / 적재 체크리스트 → 출발 버튼 활성화), 사진 증빙 업로드 → 완료
- [ ] FCM: 배정 시 푸시 발송·수신 토스트
- [ ] delivered 시 재고 차감 + `order_status_history` 기록

**완료 기준(DoD)**: 실제 주문 1건을 전화로 받아 등록 → Ганбаа 폰에 푸시 → 체크리스트 → 사진 → 완료까지 종이 없이 처리. 칸반이 실시간으로 움직인다.

## Phase 2 · 웹사이트 + 재고/리포트 (≈ 이후 1–2개월)

- [ ] 사이트 개편(`04-website-spec.md`): 히어로·카탈로그(제품 DB 연동)·무료배송 배너
- [ ] 장바구니 + 100ш 미터 → 웹 주문이 관리자 칸반 Шинэ로 직행 (source: 'website')
- [ ] `/track` 전화번호 주문조회(컨베이어)
- [ ] 재고 페이지: 입고 등록, 자동 차감 내역, 부족 경고
- [ ] 리포트: 일/월 매출, 제품별 판매량 · падаан(영수증) 인쇄(브라우저 print CSS)
- [ ] 고객 페이지: 주문 이력, Зээл(외상) 장부 `credit_balance`

**DoD**: 고객이 사이트에서 주문 → 관리자 개입 전 자동 검증(100ш·재고) → 전화번호로 스스로 상태 확인.

## Phase 3 · 음성 + 최적화 (시스템 안정화 후)

- [ ] 음성 주문 등록(BR-8): 녹음 → Chimege STT → 필드 파싱(이름·전화·지역·품목×수량) → 하이라이트 채움 → 관리자 확인 저장. 폴백 Google STT `mn-MN`
- [ ] 같은 방향 주문 묶음 배차(рейс 계획)
- [ ] 고객 SMS: `Ачаа тань замд гарлаа` (출발 시 자동)
- [ ] 기사 KPI·월간 리포트
- [ ] 필요 시 기사 앱 native 전환 검토

**DoD**: 관리자가 전화 받으며 말로 불러주면 폼이 채워지고, 확인 버튼 한 번으로 등록.

## 리스크 & 대비

- **기사 폰 오프라인**(공장 지하·외곽): SW 캐시 + 변경 큐 재전송 — P1에 포함.
- **가격 변동**: 주문 시점 `unit_price_mnt` 스냅샷 저장(이미 스키마 반영).
- **규칙 변경 가능성**: 100ш 임계값·30,000₮은 상수 분리(BR-1), 총액 기준 전환 대비.
- **iOS 웹푸시 제약**: 기사 iPhone이면 홈화면 설치 후 푸시 허용 필요 — 안내 문서 1장 준비. 안 되면 SMS 폴백.
